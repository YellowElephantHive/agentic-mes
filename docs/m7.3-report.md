## Implemented boundary

M7.3 completes the security work frozen by M7.0:

- durable authorization-decision records contain request, internal identity,
  tenant/factory scope, authentication method, issuer, role/capability
  snapshots, action/resource, outcome, sanitized denial category, duration,
  and creation time;
- pre-authentication failures use nullable identity/scope fields and never
  persist an unverified subject or bearer credential;
- successful and denied MES reads, Agent-run operations, rate limits, and
  authentication failures are audited;
- suspended users and suspended memberships fail closed;
- the OIDC suite covers malformed, expired, premature, future-issued,
  wrong-issuer, wrong-audience, modified-signature, disallowed-algorithm,
  `alg=none`, missing/unknown-`kid`, duplicate-authorization-header, unmapped
  subject, unavailable-JWKS, and development-header fallback cases;
- a key-rotation test replaces the trusted JWKS, accepts the newly trusted
  signing key, and rejects the former key; and
- token-redaction checks verify that authentication errors do not echo the
  bearer value and that the authorization-audit schema has no raw-token,
  authorization-header, signature, OIDC-subject, or raw-payload column.

Test signing keys are generated at runtime. No IdP credential, private signing
key, access token, or production identity is committed.
