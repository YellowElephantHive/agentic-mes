## Implemented scope

M8.2 generates a bounded draft from the persisted, executed evidence of one
authorized completed Agent run:

- the request can select only a frozen `proposal_type`;
- trusted server code derives summary text, recommendation codes, evidence
  state, targets, and evidence references;
- only authorized tool calls with successfully persisted results are eligible;
- result scope must exactly match the executed line and bounded time-window
  arguments;
- maintenance requires matching production and equipment-downtime evidence;
- quality requires matching production and quality-inspection evidence;
- missing, empty, denied, malformed, or mismatched profile evidence produces
  a bounded `inconclusive` proposal or fails closed;
- material-discrepancy generation remains `inconclusive` and recommends only
  physical identity inspection because no reviewed material/physical-evidence
  adapter exists; and
- database composite foreign keys bind every persisted evidence reference to
  both the proposal source run and the actual executed Agent tool call.

The implementation intentionally does not trust client/model-supplied tenant,
factory, actor, status, target, evidence, recommendation, or evidence-state
fields. Unknown fields are rejected. No LLM text can introduce a new type,
action code, target, evidence ID, capability, or authority.

## Non-goals retained

M8.2 does **not** submit, approve, reject, cancel, expire, or execute a
proposal. It does not mutate MES, ERP, PLC, equipment, inventory, quality,
work-order, genealogy, or material state. `supported` means that executed
evidence supports requesting human investigation; it is not proof of physical
root cause. AI4I and SECOM remain regression datasets, not material-identity
ground truth.
