## Implemented scope

M9.2 adds the deterministic compiler frozen by M9.0:

- compiler policy `m9.2.v1`, owned by trusted application code;
- fixed, ordered maintenance, quality, and inventory-reconciliation profiles;
- server-only compilation during action-plan creation, with no caller or model
  control over plan type, steps, order, compiler version, or timestamp;
- source proposal status, target, evidence, recommendation, count-bound, and
  cross-type validation before compilation;
- duplicate-recommendation rejection and typed step validation;
- source summary and record text treated only as data, never instructions;
- explicit persistence of source evidence state, compiler policy version, and
  compilation time;
- atomic persistence of compiled steps with proposal/review/target/evidence
  bindings and the existing idempotency record; and
- backward-readable M9.1 rows distinguished by nullable compiler metadata.

The inventory profile remains an investigation plan. Until a reviewed
physical-evidence adapter exists, material proposals compile only when the
source evidence state is `inconclusive`; compilation never upgrades it to a
confirmed material mismatch.

## Frozen profiles

- Maintenance: `machine_inspection_check`, `downtime_history_review`,
  `maintenance_evidence_collection`, `maintenance_role_notification`.
- Quality: `quality_history_review`, `quality_sample_collection`,
  `production_records_review`, `quality_role_notification`.
- Inventory reconciliation: `material_identity_inspection`,
  `inventory_records_reconciliation`, `physical_observation_collection`,
  `quality_role_notification`.

These codes describe proposed future human-controlled investigation. Their
presence does not perform the activity or create a ticket or notification.

## Explicit boundary

M9.2 does **not** implement canonical snapshots, state-drift validation,
simulation, submission, independent plan review, approval, cancellation, or
execution. There are no validate, simulate, review, or execute routes. It does
not write to MES, ERP, PLC, equipment, inventory, quality, material, or
work-order state.
