# M9.1 typed action-plan draft report

Status: **LOCAL PASS — GITHUB VERIFICATION PENDING**

Recorded on 2026-11-04 after the M9.1 implementation passed local formatting,
lint, unit, PostgreSQL integration, M8 regression, Docker reproduction, and
the independent Track A and Track B suites. The milestone remains pending
until its implementation commit passes GitHub Rust CI and both dataset jobs.

## Implemented scope

M9.1 implements only the typed draft foundation frozen by M9.0:

- typed plan-type, lifecycle-status, and bounded step registries;
- database constraints for scope, source proposal version, independent source
  review, targets, executed evidence, allowlisted steps, and lifecycle values;
- `POST /api/v1/disposition-proposals/{proposal_id}/action-plans` for an
  authorized, server-derived draft from a `review_approved` M8 proposal;
- `GET /api/v1/action-plans/{plan_id}` with self/tenant authorization and
  resource hiding;
- server-copied source targets and evidence, exact proposal version, approving
  review, creator, tenant/factory scope, 24-hour expiry, and version 1;
- idempotent creation with same-request replay and conflicting-key rejection;
- production-analyst self read and supervisor/admin tenant read capability
  bundles; and
- sanitized authorization-decision auditing for create and read operations.

The M9.1 record is an **uncompiled typed shell**. Its `steps` collection is
empty, and its snapshot and simulation bindings are null. The request body is
empty and rejects caller-supplied steps or trusted-field overrides.

## Explicit boundary

M9.1 does **not** implement compilation, state snapshotting, drift validation,
simulation, submission, independent plan review, approval, or execution.
There are no validate, simulate, review, or execute routes or capabilities.
Creating or reading a draft does not write to MES, ERP, PLC, equipment,
inventory, quality, material, or work-order state.
