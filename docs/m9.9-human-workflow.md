# M9.9 Human Workflow Surfaces

Status: **PASS**

M9.9 exposes the already verified M8/M9 human-controlled lifecycle in the
local browser console. It does not add a new domain transition, capability,
repository mutation, execution route, or manufacturing-system credential.

## Start the workflow

```bash
./scripts/run-console.sh
```

Open `http://127.0.0.1:8080`, run the production investigation, and continue
through the Human workflow panel. The launcher seeds a local-only independent
reviewer named `m9-demo-reviewer`; it never creates a production identity.

## Implemented in M9.9

- evidence-bound maintenance proposal creation from the active Agent run;
- creator-controlled proposal submission;
- explicit independent reviewer identity, rationale, approval, and rejection;
- deterministic approved-proposal-to-action-plan compilation;
- creator-controlled validation, isolated simulation, and submission;
- independent action-plan approval and rejection;
- visible record IDs, optimistic versions, statuses, and simulation safety
  result; and
- responsive human workflow cards embedded in the Rust API binary.

Every transition uses the existing authenticated API with an idempotency key.
State transitions use `If-Match`, reviewer calls use a distinct local identity,
and server-side capability and separation-of-duties checks remain authoritative.
The browser cannot supply proposal targets, evidence references, plan steps,
compiler policy, validation snapshot, simulation seed, or trusted bindings.

## Intentionally not implemented

M9.9 is a single active-case demonstration, not a general work queue. It does
not add proposal or plan list/search endpoints, cross-session case recovery,
notifications, external ticket export, production sign-in, or production IdP
administration. Most importantly, it has no execute button or execute route.
`plan_approved` records human acceptance of a non-executable investigation plan
only.

## Acceptance gate

M9.9 passes only when:

1. embedded asset tests prove that the human workflow is shipped and no
   `/execute` route is referenced;
2. the one-command HTTP demo completes proposal and plan independent reviews;
3. browser QA reaches `review_approved` and `plan_approved` through the visible
   controls while reporting protected state unchanged;
4. the formal Rust and adversarial M9 suite passes;
5. Track A and Track B pass independently; and
6. the aggregate dual-track gate passes.

Local browser success is presentation evidence, not a substitute for the
deterministic gates above.
