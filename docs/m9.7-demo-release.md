# M9.7 demo-ready release

Status: **PASS**

M9.7 packages the completed M9 lifecycle as a reproducible portfolio demo. It
does not extend the M9 authority boundary or add an execution path.

## One-command walkthrough

Prerequisites are Rust 1.85+, Docker with Compose, `curl`, and `jq`.

```bash
./scripts/demo-m9.sh
```

The script owns an isolated Compose project and uses host ports `55432` and
`58080` by default. It seeds deterministic factory data, starts the API with
the mock provider, creates an independent development reviewer, and exercises:

```text
source-grounded Agent run
  -> supported M8 proposal
  -> independent proposal approval
  -> deterministic M9 plan compilation
  -> canonical validation snapshot
  -> isolated deterministic simulation
  -> independent plan approval
  -> non-executable plan_approved record
```

It also proves two fail-closed cases: a client-supplied simulation seed is
rejected with HTTP 422 and the plan creator cannot approve their own plan
(HTTP 403). The result is written to `artifacts/m9.7-demo.json`; runtime UUIDs
vary, while the seeded manufacturing state and deterministic policy outputs
remain reproducible.

Set `DEMO_POSTGRES_PORT`, `DEMO_API_PORT`, or `DEMO_OUTPUT` to override local
ports or the ignored result path. Cleanup stops the API process and removes
the isolated database volume.

## Acceptance gate

M9.7 passes only when all of the following succeed for the same implementation
commit:

- the one-command HTTP demo in its independent GitHub CI job;
- the Rust/formal M9 CI job;
- Track A independently;
- Track B independently; and
- the aggregate dual-track gate.

`plan_approved` remains an audited human acceptance record. It does not create
tickets, export commands, contact equipment, or write to MES, ERP, QMS, WMS,
or PLC systems.
