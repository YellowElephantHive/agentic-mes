## Implemented scope

M9.3 implements deterministic validation policy `m9.3.v1`:

- `POST /api/v1/action-plans/{plan_id}/validate` with M7 authentication,
  `validate:action_plans`, creator ownership, `Idempotency-Key`, and positive
  optimistic `If-Match` version;
- source proposal version, approved review history, plan type, source evidence
  state, compiler metadata, and exact frozen-step-profile verification;
- ordered target and authorized executed-evidence resolution inside the
  authenticated tenant/factory transaction;
- canonical line state containing bounded counts and SHA-256 hashes for work
  orders, production records, downtime events, and quality inspections;
- canonical machine state containing current status and bounded downtime
  count/hash;
- versioned canonical JSON, stable SHA-256 snapshot hash, explicit missingness,
  64 KiB payload bound, 16-target bound, and 8-evidence bound;
- append-only `action_plan_snapshots` and sanitized validation audits;
- deterministic revalidation: unchanged trusted inputs retain the same hash;
- fail-closed drift handling that returns `409 action_plan_drifted`, increments
  the optimistic version, and moves the plan to terminal
  `invalidated_by_drift`; and
- idempotent success and drift replay plus incompatible-key and stale-version
  conflict rejection.

Snapshot payloads contain stable identifiers, bounded counts, status fields,
explicit missingness, and hashes. They do not copy raw manufacturing records,
raw tool results, prompts, credentials, or provider secrets. Dataset source
records and all operational manufacturing tables remain unchanged by
validation.

## Drift coverage

The canonical hash changes when relevant trusted state changes, including:

- work-order status, quantity, due date, or version timestamp;
- production, downtime, or quality rows for a target line;
- machine status or machine downtime history;
- ordered target, evidence, source proposal/review, or compiled-step binding;
  or
- validation policy version.

Inventory and physical material identity adapters remain unavailable and are
recorded as missing for inventory-reconciliation snapshots. Missingness is not
silently imputed and cannot become a confirmed material-mismatch claim.

## Explicit boundary

M9.3 does **not** implement simulation, submission, independent plan review,
approval, cancellation, or execution. There are no simulate, review, or
execute routes. Validation reads trusted state and updates only action-plan
validation records; it does not write to MES, ERP, PLC, equipment, inventory,
quality, material, work-order, source-proposal, source-review, evidence, or
dataset state.
