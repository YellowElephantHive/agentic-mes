## Implemented scope

M8.3 implements the frozen proposal lifecycle without adding execution
authority:

- initiator-only `draft -> pending_review` submission;
- initiator-only cancellation from `draft` or `pending_review`;
- approval or rejection by a different locally authorized reviewer;
- explicit separation of duties: an initiator with supervisor/admin role still
  cannot review their own proposal;
- server-clock expiry from `pending_review` after resource authorization;
- terminal-state transition rejection;
- positive `If-Match` version preconditions and version increments for every
  completed transition;
- `Idempotency-Key` replay and incompatible-reuse conflict handling;
- append-only single review decisions with tenant/factory scope;
- sanitized successful transition audits containing source run, prior/result
  status and version, actor, evidence count, and idempotency outcome; and
- resource authorization before any expiry side effect.

The lifecycle endpoints are:

```text
POST /api/v1/disposition-proposals/{proposal_id}/submit
POST /api/v1/disposition-proposals/{proposal_id}/cancel
POST /api/v1/disposition-proposals/{proposal_id}/reviews
```

Approval records only that a human accepted the recommendation. There is no
execution endpoint, execution capability, MES write adapter, or implicit
operational side effect.
